## Delivered V6 delta

### Product and Find interaction

- Find now has one intentional scroll region and a drawer-local sticky action footer. The primary action remains reachable at the tested short desktop height, and the `Data & methodology` disclosure is constrained horizontally and vertically rather than clipping outside the drawer.
- Duplicate permanent disclaimers and the duplicate mode label were removed. Source, current map extent, bounded-sample limitations, prohibited claims, ODbL attribution and the screening caveat remain accessible in one disclosure.
- A successful Find result, shortlist and exact source lineage remain visible when viewport, market, locale, audience, role, scenario, object group or minimum mapped levels change. The result becomes visibly stale and the action changes to Update search; the changed controls are not misrepresented as new evidence.
- Session restoration retains the last successful result and its original query context. Dynamic lineage records OpenStreetMap/Overpass provenance, retrieval time, query extent and deterministic query hash.
- If the current map market differs from the result's original market, candidate analysis is disabled. Switching market clears the map selection, and a map click in Find mode does not recreate an Analyse selection. This prevents cross-market identity/context requests.

### Product and decision architecture

- `GeoContextSnapshot V1` defines one immutable, locale-independent, content-addressed evidence record for a point, mapped object, site or AOI, including provenance, measured coverage, freshness, confidence, conflicts, gaps and tuple-scoped rights gates.
- `Scenario Registry V1` versions role/scenario applicability, required context, methods, metrics, templates, validation obligations and ranking enablement. Ranking remains disabled until evidence comparability and method gates pass.
- `DecisionRecord V1` binds scenario, subject, snapshot, method, metrics, alternatives, risks, gaps and recommendations into one immutable decision graph. Dashboard, comparison and report are specified as projections of that record, not independent calculators.
- `DecisionRenderReceipt V1` keeps localized rendering outside the truth hash, requires an exact finalized parent and enforces parent -> artifact -> receipt chronology.
- The focused Ajv 2020 checker validates four schemas, four positive fixtures and 24 negative invariants, including hash tamper detection, locale neutrality, exact reference resolution, conditional/share-alike fail-closed behavior, immutable operation/channel/delivery/territory/time/scope/evaluator rights tuples, and blocked-parent render monotonicity.

This constitutes G1 contract acceptance plus a focused executable contract checker. It does not constitute full G2: production TypeScript parsers, exhaustive parent/fact graph and cycle enforcement, cohort/ranking reconciliation, render-manifest allowlisting, artifact-byte verification and an obligation-satisfaction receipt remain open.

### Generative-development sourcing decision

- The research package separates customer jobs, paid value, data/rules, geometry, optimization, simulation, BIM/digital-twin, rendering and API/MCP concerns rather than treating "AI generation" as one component.
- The controlling matrix covers 21 product/runtime rows across 25 fields and records evidence class or controlled unknown for every cell.
- Current recommendation: provider-neutral hybrid. GeoAI owns GeoContext, Scenario Registry, constraints, evaluation, economics, explainability, decision workflow and API/MCP; specialist geometry, optimization, simulation, BIM/export or digital-twin components enter only after an identical UAE bake-off and written rights review.
- Public evidence does not yet verify authority-grade UAE rule coverage, wider GCC coverage, complete OEM/headless/output/post-termination rights, named-pilot security/data-region fit, quantified three-year TCO or paid-customer validation for any proprietary provider. No vendor selection is made by this receipt.
