## Problem and business reason

1. The Find drawer spends scarce vertical space on repeated caveats, nested containers and an action that can scroll out of view. This weakens the primary criteria-first task.
2. Existing product capabilities are split across current and prior implementations. Reintroducing old mock scoring would create false precision, while discarding all prior work would waste useful interaction and reporting patterns.
3. Analyse, Find and Create currently have route-specific representations of context. Without one versioned GeoContext and Decision Record, the same site can produce inconsistent search, comparison, dashboard and report outputs.
4. Create demonstrates reversible massing but is not yet a defensible generative-development workflow. It needs context, constraints, deterministic metrics, variant comparison and validation before visual sophistication.
5. The market already contains established feasibility, GIS, digital-twin, BIM and generative-design engines. Building every layer internally before a structured bake-off would create avoidable cost and lock GeoAI into unvalidated assumptions.

## Users and decisions

- Real-estate developers, investment/deal teams and development managers: screen sites, reject weak opportunities quickly and compare feasible development directions.
- Architects, planners and consultants: convert site context and constraints into early alternatives and a traceable client decision package.
- Funds, lenders and asset managers: review assumptions, evidence, risks, economics and change between alternatives.
- Public-sector and B2G users: compare development or regeneration hypotheses while keeping official validation and decision authority outside the model.
